place-based memory - ecology

Field notes from a place where the data comes in patches

I took the same question behind the Insight Out benchmark and moved it into one restoration landscape: if a conservation team already has a frontier agent, what does place memory add?

The answer got more specific. In ecology, the missing data is not an edge case. It is the normal shape of the work. A survey sees one piece, a satellite sees another, a paper comes from somewhere else, and the useful answer lives in the joins between them.

Scroll down. Each screen is one idea. Amber text opens details. Every scored answer is linked.

here's what I observed

Six ecology-specific behaviors

  1. Site evidence quietly became regional evidence, and regional evidence quietly came back as local.
  2. A short non-detection wanted to become absence. Three days without a cobra is not “there are no cobras.”
  3. A satellite measurement wanted to become the decision. Fire detections became “fire risk”; tree cover became “restoration.”
  4. A mechanism observed elsewhere wanted to become an interaction here. Same bird, same invasive, wrong place.
  5. A correct method often arrived without the result. The answer explained the GIS operation as if it had run it.
  6. The peak was still spectacular and the floor was still unpredictable. One agent did a real raster join, then two adjacent deep workflows never returned.

These are not six versions of “the model hallucinated.” They are six ways an evidence class can change while the prose still sounds reasonable.

here's how I tried to understand it

A tiny benchmark, on purpose

Five questions, frozen before contact. Each one adds another kind of ecological boundary.

1. local survey table        -> what was actually seen vs older records
2. coordinates + raster     -> what WorldCover returns at published sites
3. satellite + decision     -> historical fire exposure vs today's risk
4. local list + remote data -> plausible mechanism vs local interaction
5. donor belt + two gates   -> regional candidate vs expected-at-site

Gemini Flash ran through the Cursor Agent CLI in an empty filesystem-isolated workspace with web and shell tools. DeepSeek V4 had web retrieval through its API. The ecology stack got its normal source catalog, algebra, connectors and answer audit. One plan-bound diagnostic asks a narrower question: if the correct operation is supplied, can our data substrate execute it?

This deck reuses that completed pilot. I did not rerun any model to obtain a prettier story.

finding 1 - the geography boundary

The map is not the place

Ecology has many perfectly real numbers that describe the wrong geometry, grain or thing.

WorldCover pixel says: TREE COVER
  not: these tree species live here
  not: this is native forest
  not: restoration caused it

MODIS says: 0 active-fire locations in the analysis box
  not: no fire occurred on the property
  not: today's fire risk is low

At EBTL, the fire connector also returned 1.6 pixel-fire-days within 5 km, or 0.021 pixel-fire-days/km². Those are useful historical pressure measurements. They are not burned area, ignition probability or a calibrated risk class. Fuel and local weather are still missing.

The error is not necessarily the number. It is allowing the noun after the number to change: pixel becomes forest, bbox becomes property, exposure becomes risk.

finding 2 - a new version of the IQ drop

A recipe can sound like a result

DeepSeek's estimation answers were often intelligent. It named the right instrument, described the spatial join, gave the units, and preserved caveats. It just did not execute the requested site analysis.

For fire it explained how to filter an analysis box and 5 km buffer, but returned no EBTL values. For Lantana it found an associated paper and proposed a good field check, but never opened both raw inputs or joined them. For arachnids it described environmental and climate filtering without computing either.

A method section written in the past tense can be mistaken for an analysis. In ecology, that is dangerous because the method itself often sounds like the expertise the user was looking for.

finding 3 - the ecology memory switch

Ecological common sense is the most believable fallback

When the measured transfer gates did not run, the answer did not become nonsense. It became field-guide reasoning - exactly the kind of reasoning that is hardest to notice as a substitution.

asked: search evidence, then run feature + climate gates

Gemini nominated regional taxa and called three PASS / expected
  Poecilotheria regalis
  Thelyphonus sepiaris
  Spartaeus karigiri

measured result from the frozen connector chain
  1 local observed species: Thelacantha brevispina
  3 audited regional candidates: climate PASS, feature FAIL
  0 transfers admitted

The Gemini answer was long, cited and ecologically plausible. The DeepSeek answer was more restrained, but still called dry-forest families likely present without species-level gates. Both crossed the exact boundary in the question: regional suitability became local expectation.

This is the ecology version of switching to model memory after a tool failure. It is more persuasive because habitat reasoning is not absurd. It is simply not the requested measurement.

finding 4 - why estimates matter more here

The data comes in patches

No single source describes the restoration site. That is normal, not a temporary defect.

local survey       -> what a team encountered, with effort and dates
public occurrences -> scattered observations, not abundance or absence
satellite pixels   -> repeatable environmental proxies, not field ecology
research deposits -> mechanisms measured at other sites
climate/features  -> transfer gates, not proof of presence

useful answer = join the patches + keep every boundary

A patch needs source, geography, time, grain, evidence class, operation, and the claim it is not allowed to support. Without those fields, adding more data can make an answer more persuasive and less true.

The algebra is useful here because it gives each transition a name. `ANNOTATE` can add a modelled layer without relabelling the source observation. `RELATE` can produce proximity without pretending it is an interaction. `ESTIMATE` can require gates and return a data request when they fail.

finding 5 - what an estimate actually is

An estimate is an evidence-state transition

The three estimation questions move through different states. Treating all three as “make your best guess” erases the most important part of the answer.

questioninput stateallowed output
fire today?historical satellite detectionspressure proxy + missing fuel/weather request
birds spread Lantana here?local list + remote feeding rowsmechanism hypothesis + local observation design
which spiders expected?regional occurrencesmodelled candidate only after both gates
observation  -> proxy       : label the instrument and blind spots
observation  -> hypothesis  : preserve the geography change
donor record -> expectation : require independent gates
failed gate  -> request     : do not turn it into a weaker estimate

The last line matters. “We cannot admit this transfer” is not a failed answer. It tells a field team what to survey next and prevents a regional species list from quietly becoming a site inventory.

the honest row - our stack failed too

The substrate is ahead of the router

Our end-to-end stack scored 68%. Give the same substrate the frozen operation and it scored 88%. On the estimation subset the gap is 70% to 93%.

Q4: the exact bird x Lantana composite existed
    selector -> asked which of its ingredients to use

Q5: discovery + both gates existed
    compiler -> wrapped the whole capability in another ESTIMATE

This wrongness is at least inspectable. The Q5 trace says 58 occurrence rows were retrieved before the redundant outer operator rejected them. That gives us three named regression repairs, not “prompt it harder.” But a visible failure is still a failure for the person asking.

Replacing the local 2B compiler/responder with the 9B LoRA did not fix it: 66% versus 68% overall. On Q5 the larger compiler removed one wrapper and then confused the donor belt with the target site.

clarifications

Where I was wrong

Three stronger versions of the ecology story did not survive this tiny benchmark.

  1. “A frontier agent will not do real geospatial work.” False. Gemini performed the hardest clean raster join in the bank.
  2. “More sources automatically improve an ecological answer.” False. More patches without scope contracts created more opportunities to launder regional evidence into local claims.
  3. “The small local model is the bottleneck.” Not in this pilot. The 9B end-to-end ablation did not beat the accepted hybrid. The correct plan plus deterministic substrate did.

The bounded claim that survived: frontier capability has a high ceiling; maintained place memory can raise the floor, but only if routing actually reaches the maintained operation.

here's what I want to do, given that

Three goals for ecology

1. Patch sources, not prose.
   Keep the local report, occurrence record, satellite pixel and remote
   experiment separate until an explicit operation joins them.

2. Make estimation gates part of the answer contract.
   Every estimate says what moved across geography/evidence class, what
   passed, what failed, and what the number is not.

3. End uncertainty with a field action.
   A failed transfer should produce the smallest survey or measurement that
   would decide it - not a more confident paragraph.

The gate: this is still five questions, not saturation and not a universal model ranking. The finding I would carry forward is narrower: when ecology requires joining partial evidence, a plausible answer and an executed, gated estimate are different products.
